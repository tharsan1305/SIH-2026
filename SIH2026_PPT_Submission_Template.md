# SIH 2026 — PPT Submission Template (6-Slide Structure)

**Purpose:** A ready-to-follow slide-by-slide template for your SIH 2026 Internal Hackathon / Idea Presentation PPT. Fill in each section for your chosen problem statement and build your slides directly from this structure.

**Format note:** SIH typically expects a **single-page PPT per slide topic**, clean and visual (not text-heavy). Use this MD as your content-planning doc first, then design the actual `.pptx` using it.

---

## 🗂️ Slide-by-Slide Workflow (6 Slides)

```
Slide 1 → Title Slide (Team + Problem Statement Info)
Slide 2 → Problem Statement / Idea Overview
Slide 3 → Proposed Solution / Approach
Slide 4 → Technical Feasibility & Tech Stack
Slide 5 → Impact & Benefits (Social/Economic/Environmental)
Slide 6 → Research & References / Team Details
```

---

## 📑 SLIDE 1 — Title Slide

**What to include:**
- Team Name
- Problem Statement ID (e.g., SIH26071)
- Problem Statement Title (exact, from official PDF)
- Theme name
- Organization/Ministry (the PS owner)
- Category: Software / Hardware
- Team members' names + roles (optional, some rounds require this)
- College/Institution name + logo

**Design tip:** Keep it minimal — logo, PS ID, title, team name, and a clean background. This is the first impression; don't overcrowd it.

```plaintext
Fill-in template:
- Team Name: [__________]
- PS ID: SIH26[___]
- PS Title: [_________________________]
- Theme: [_________________________]
- Organization: [_________________________]
- Category: [ ] Software  [ ] Hardware
- Team Members: [Name 1], [Name 2], [Name 3]...
```

## 📑 SLIDE 2 — Problem Statement / Idea Overview

**What to include:**
- Restate the problem in your own words (2-3 lines max)
- Who is affected? (target users/beneficiaries)
- Current situation / pain point — what's broken or missing today
- Why does this problem matter? (1-2 sentences on urgency/scale)

**Design tip:** Use a simple visual — an icon-based "before" scenario, or a short bullet list. Avoid copy-pasting the official PS description word-for-word; show you understood it.

```plaintext
Fill-in template:
- Problem in one line: [_________________________]
- Who is affected: [_________________________]
- Current gap/pain point: [_________________________]
- Why it matters (scale/urgency): [_________________________]
```

---

## 📑 SLIDE 3 — Proposed Solution / Approach

**What to include:**
- Your solution in one clear sentence (the "elevator pitch")
- Key features (3-5 bullet points, not paragraphs)
- A simple flow diagram or architecture sketch (block diagram: Input → Processing → Output)
- What makes it different/better than existing solutions (your differentiation angle)

**Design tip:** This is the most important slide — use a visual diagram, not just text. A simple boxes-and-arrows flow works well.

```plaintext
Fill-in template:
- Solution in one sentence: [_________________________]
- Key Feature 1: [_________________________]
- Key Feature 2: [_________________________]
- Key Feature 3: [_________________________]
- Differentiation from existing solutions: [_________________________]
```

## 📑 SLIDE 4 — Technical Feasibility & Tech Stack

**What to include:**
- Tech stack used: Frontend / Backend / Database / AI-ML / Hardware components
- Any APIs, datasets, or open-source tools you're using (name them — e.g., IMD API, Bhashini, OpenCV)
- High-level architecture diagram (can reuse/extend the one from Slide 3)
- Feasibility statement — why this is buildable in the given timeframe

**Design tip:** Use logos/icons for tech stack (React, Python, TensorFlow icons etc.) instead of plain text lists — much more visual and judge-friendly.

```plaintext
- Backend: [_________________________]

- AI/ML (if any): [_________________________]
- Hardware components (if any): [_________________________]
- Key APIs/Datasets used: [_________________________]
- Feasibility note: [_________________________]
```

## 📑 SLIDE 5 — Impact & Benefits

**What to include:**
- Social impact (who benefits, how many people, quality-of-life improvement)
- Economic impact (cost savings, revenue potential, efficiency gains)
- Environmental impact (if applicable)
- Scalability — can this expand beyond the pilot use case? (e.g., state → national level)
- Use Low/Medium/High framing — **do not invent specific numbers/market-size figures** you can't back up

**Design tip:** Use 3 icon-based columns (Social / Economic / Environmental) rather than a wall of text.

```plaintext
Fill-in template:
- Social impact: [_________________________]
- Economic impact: [_________________________]
- Environmental impact (if applicable): [_________________________]
- Scalability potential: [_________________________]
```

---

## 📑 SLIDE 6 — Research & References / Team Details

**What to include:**
- Key research sources/references you used (official data sources, existing solutions studied)
- Brief note on existing solutions and how yours differs (1-2 lines — shows you did competitive research)
- Team member names + their roles/skills (if not on Slide 1)
- Contact info (optional, some formats want this)
- Thank you / closing note

**Design tip:** This slide builds credibility — showing real references (not made-up ones) signals a serious, research-backed team.

## ✅ Pre-Submission Checklist

Before finalizing your PPT, check:

- [ ] PS ID and title match EXACTLY with the official SIH portal listing
- [ ] No plagiarized/copy-pasted content from other team's or company's materials
- [ ] All diagrams are original (hand-made or created by your team, not copied images)
- [ ] Tech stack listed is realistic for your team to actually build
- [ ] Impact claims use Low/Medium/High or qualitative language — no invented statistics
- [ ] References are real, verifiable sources
- [ ] Spelling/grammar checked
- [ ] File size and format match the official submission guidelines (check SIH portal for exact PPT format/template requirements)

---

## ⚠️ Common Mistakes to Avoid

1. **Text-heavy slides** — judges skim fast; use bullets + visuals, not paragraphs.
2. **Copying the problem statement description verbatim** — shows no original understanding.
3. **No differentiation slide/section** — if you don't explain why your solution is different, it looks like "just another version of X."
4. **Overpromising impact** — vague "will help millions of farmers" claims without reasoning look weak. Explain the reasoning briefly instead.
5. **Ignoring the official PPT template** — many SIH rounds provide a mandatory PPT template on the portal. Always check and use the official one if provided; this MD is for **content planning**, not a replacement for the official format.
